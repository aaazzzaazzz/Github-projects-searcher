# 活跃度计算方法详细说明

## 概述

本项目的活跃度计算采用多维度综合评估方法，结合了GitHub事件数据和项目指标数据，通过科学的权重分配来量化项目的活跃程度。

## 活跃度数据来源

### 1. 主要数据源

#### GitHub事件数据 (github_events表)
- **IssuesEvent**: 问题相关事件
- **PullRequestEvent**: 拉取请求事件
- **PushEvent**: 代码推送事件
- **ForkEvent**: 分叉事件
- **ReleaseEvent**: 发布事件

#### 项目指标数据 (projects.metrics_data字段)
- **Activity_Metrics**: 活跃度指标
  - `activity_Latest`: 最新活跃度值
  - `activity_Average`: 平均活跃度
  - `activity_Data_Points`: 数据点数量
  - `code_change_count_Latest`: 最新代码变更数量
  - `issue_opened_Latest`: 最新开启的问题数量
  - `pull_request_opened_Latest`: 最新开启的拉取请求数量
  - `release_count_Latest`: 最新发布数量

#### 贡献者数据 (Contributor_Metrics)
- `new_contributors_Latest`: 最新新增贡献者数量
- `inactive_contributors_Latest`: 最新非活跃贡献者数量

## 活跃度计算公式

### 1. 基础活跃度分数计算

```python
def _calculate_activity_score(self, activity_stats: Dict[str, int]) -> float:
    """计算活跃度分数"""
    total_events = activity_stats.get("total_events", 0)
    unique_contributors = activity_stats.get("unique_contributors", 0)
    
    # 排除DeleteEvent，因为它不代表积极的活动
    positive_events = (
        activity_stats.get("issues_events", 0) +
        activity_stats.get("pull_request_events", 0) +
        activity_stats.get("push_events", 0) +
        activity_stats.get("fork_events", 0) +
        activity_stats.get("release_events", 0)
    )
    
    # 基于积极事件和贡献者数量计算活跃度
    score = (positive_events * 2.0) + (unique_contributors * 5.0)
    return round(score, 2)
```

**公式**: `活跃度分数 = (积极事件数 × 2.0) + (唯一贡献者数 × 5.0)`

### 2. 优先使用高级指标数据

系统会优先从`metrics_data`中的`Activity_Metrics`获取更准确的活跃度分数：

```python
# 从Activity_Metrics中获取活跃度分数
if 'Activity_Metrics' in metrics_data:
    activity_metrics = metrics_data['Activity_Metrics']
    activity_latest = activity_metrics.get('activity_Latest')
    if activity_latest is not None and activity_latest != 'null':
        activity_score = float(activity_latest)
```

## 活跃度级别分类

### 动态阈值计算

系统根据当前数据分布动态计算活跃度阈值：

```python
max_score = max(scores)
min_score = min(scores)

# 动态计算阈值：基于实际数据分布
high_threshold = max_score * 0.7      # 前30%为高活跃度
medium_threshold = max_score * 0.3   # 30%-70%为中等活跃度
low_threshold = max_score * 0.1      # 后10%为低活跃度
```

### 活跃度级别定义

1. **高活跃度 (High Activity)**: `activity_score > high_threshold`
   - 占所有项目的前30%
   - 表示项目非常活跃，有大量的事件和贡献者

2. **中等活跃度 (Medium Activity)**: `medium_threshold < activity_score <= high_threshold`
   - 占所有项目的中间40%
   - 表示项目有适度的活跃度

3. **低活跃度 (Low Activity)**: `activity_score <= medium_threshold`
   - 占所有项目的后30%
   - 表示项目活跃度较低

## 权重分配说明

### 事件权重
- **积极事件权重**: 2.0
  - IssuesEvent: 问题事件
  - PullRequestEvent: 拉取请求事件
  - PushEvent: 代码推送事件
  - ForkEvent: 分叉事件
  - ReleaseEvent: 发布事件

- **贡献者权重**: 5.0
  - 每个唯一贡献者贡献5.0分
  - 贡献者多样性比事件数量更重要

### 权重设计理念
1. **贡献者权重更高**: 鼓励社区参与和多样性
2. **排除消极事件**: DeleteEvent不计入活跃度
3. **综合评估**: 结合事件数量和参与者多样性

### 月度活跃度统计
系统按月统计项目活跃度：
```python
activity_stats = session.query(
    GitHubEvent.project_key,
    extract('year', GitHubEvent.created_at).label('year'),
    extract('month', GitHubEvent.created_at).label('month'),
    func.count(GitHubEvent.id).label('total_events'),
```

- 考虑不同事件类型的相对重要性

### 2. 时间衰减
- 考虑加入时间衰减因子
- 近期活动权重更高

### 3. 质量指标
- 结合代码质量指标
- 考虑维护响应时间

## 总结

本活跃度计算方法通过多维度数据综合评估，既考虑了项目的活动频率，也重视社区参与度。动态阈值机制确保了分类的相对公平性，而优先使用高级指标数据保证了计算的准确性。这种方法为项目评估和搜索提供了科学可靠的活跃度量化标准。
